# 回归测试 Web 管理页使用说明

本文说明 `regression_mvp` 本地 Web 管理页的启动方式和各页面按钮含义。

## 1. 启动前准备

先启动被测 API：

```powershell
Copy-Item -Force docker/local/.env.local .env
.venv\Scripts\python.exe -m uvicorn src.main:app --port 6300
```

如果测试链路依赖异步任务，另开窗口启动 Worker：

```powershell
.venv\Scripts\python.exe -m arq src.worker.WorkerSettings
```

确认 API 可访问：

```text
http://localhost:6300/swagger#/
```

如果接口依赖公司内网服务，需要先连接公司 VPN。Web 页面里的环境检查也是以 Swagger 地址为准。

## 2. 启动 Web 管理页

推荐在 PyCharm 中直接运行：

```text
regression_mvp/web_app/run_web.py
```

也可以用命令行启动：

```powershell
.venv\Scripts\python.exe -m uvicorn regression_mvp.web_app.app:app --host 127.0.0.1 --port 6400
```

浏览器访问：

```text
http://127.0.0.1:6400
```

如果页面没有显示最新功能，先停止旧的 6400 端口进程，再重新启动 Web。

## 2.1. 首次拉取代码后的用例同步

正式用例、候选用例和历史归档文件不再通过 Git 同步，而是由团队共享 MinIO 管理。首次拉取代码后，如果 `用例` 或 `候选` 页面为空，按下面步骤处理：

1. 确认已经连接公司 VPN，并且 `.env` 中的 MinIO 配置可用。
2. 启动 Web 管理页。
3. 打开 `MinIO` 页面，确认 bucket 为 `regression-mvp-dev`。
4. 点击 `从 MinIO 刷新全部`，把远端正式用例和候选用例下载到本地工作区。

本地目录 `regression_mvp/cases/`、`regression_mvp/case_candidates/`、`regression_mvp/case_history/`、`regression_mvp/reports/` 和 `regression_mvp/.sync_state/` 都属于运行数据，不需要提交到 Git。

## 3. 页面导航

顶部导航包含：

| 页面 | 用途 |
| --- | --- |
| 总览 | 查看环境、选择接口运行、查看最近接口状态 |
| 接口 | 按业务分组查看已接入接口、运行单个接口 |
| 用例 | 管理正式回归用例 |
| 候选 | 上传文件生成候选用例、确认并固化 |
| MinIO | 查看团队共享用例存储状态、执行集中同步、查看冲突报告 |
| 报告 | 查看和删除历史测试报告 |
| 运行 | 查看 Web 触发的测试运行状态和日志 |

## 4. 总览页

总览页顶部是环境检查，用于确认 API 是否可访问。

执行入口支持选择一个或多个接口运行：

- 只选一个接口：生成单接口报告。
- 选择多个接口：除各接口自己的报告外，还会生成一份多接口汇总报告。

最近接口状态展示每个接口最近一次运行结果、通过率和 HTML 报告入口。

## 5. 接口页

接口页按业务分组展示接口，命名和项目 API 页面保持一致。

常用操作：

- `运行`：只运行当前接口的启用用例。
- `详情`：进入该接口的用例或报告详情。
- `HTML`：打开最近一次 HTML 报告。

接口页适合按接口维度快速查看覆盖情况和最近结果。

## 6. MinIO 页

MinIO 页用于集中查看正式用例和候选用例的共享存储状态。

页面顶部展示当前配置：

- 是否启用 MinIO 同步。
- MinIO endpoint。
- bucket。
- prefix。

对象统计区展示：

- 本地正式用例数量。
- 本地候选用例数量。
- 远端正式用例数量。
- 远端候选用例数量。

常用操作：

- `重新扫描`：重新检查本地工作区与 MinIO 远端状态，只更新页面提示，不上传、不下载、不覆盖文件。
- `从 MinIO 刷新全部`：把远端正式用例和候选用例拉取到本地工作区。
- `上传本地全部`：把本地正式用例和候选用例发布到远端。

如果远端不可访问，页面仍可打开，并会显示远端统计获取失败的原因。

Web UI 启动时会自动执行一次后台扫描，结果写入：

```text
regression_mvp/.sync_state/sync_status.json
```

启动扫描不会自动同步文件。它只用于提示：

- 本地疑似未发布对象数量。
- 远端疑似未拉取对象数量。
- 本地和远端同时修改的冲突风险。
- 缺少共同基线的对象。
- MinIO 历史版本缓存是否超过提醒阈值。

历史版本提醒只提示用户维护，不会自动删除 MinIO 对象。相关阈值可以通过环境变量调整：

```text
REGRESSION_MVP_MINIO_CLEANUP_KEEP_VERSIONS=10
REGRESSION_MVP_MINIO_WARN_HISTORY_VERSIONS=20
REGRESSION_MVP_MINIO_WARN_HISTORY_MB=1024
```

最近同步记录区展示最近的手动同步和自动同步失败记录，包括：

- 操作类型。
- 目标用例或候选。
- 上传、下载、删除、跳过、冲突数量。
- 失败分类和建议下一步。

常见失败会被归类为网络/VPN 问题、权限或凭证错误、bucket 不存在、远端对象不存在、版本冲突、路径不合法、文件校验失败等。

远端历史版本清理区用于控制 MinIO 空间增长：

- `预览清理`：按“保留版本数”计算会删除哪些旧版本对象，不立即删除。
- `确认清理远端历史版本`：根据预览策略删除 MinIO 上未被保留版本引用的旧对象。

系统会始终保留 current 指向的版本，以及最近 N 个版本。因为新版本可能复用旧版本里的未变化文件，清理时不会简单删除整个旧版本目录，而是只删除没有被保留版本 manifest 引用的对象。

预览结果只展示存在待删版本的对象；没有待删版本的对象不会出现在明细表里，避免对象多时页面过于冗余。

本地归档清理规划区用于观察和清理本机归档目录。点击 `重新计算` 会按保留天数预览待清理条目；点击 `确认清理本地归档` 后，系统只会删除这些白名单目录中超过保留天数的条目：

- `case_history/`
- `case_archive/`
- `reports/_archive/`
- `.sync_state/conflicts/resolved/`

本地归档清理不会删除 MinIO，也不会删除 `cases/`、`case_candidates/`、`reports/{endpoint}/runs/` 等活跃目录。执行前会弹出二次确认。

冲突报告区会列出 `.sync_state/conflicts/` 下的冲突 JSON 文件。点击 `详情` 可以查看每个冲突文件的本地状态、远端状态、Hash 和可选处理方式。

冲突详情页支持：

- `采用远端`：用 MinIO 当前版本覆盖本地工作区，并更新本地同步基线。
- `强制采用本地`：把当前本地目录发布为 MinIO 新版本，并更新远端 current 指针。
- `标记已处理`：只把冲突报告移入 resolved 目录，不修改本地或远端文件。

处理后的冲突报告会移动到：

```text
regression_mvp/.sync_state/conflicts/resolved/
```

## 7. 用例页

用例页管理已经固化的正式回归用例。

筛选区支持：

- 按接口筛选。
- 按启用状态筛选。
- 按关键字搜索 case、endpoint、description。

文件预览区使用中文链接名：

- `用例配置`：打开 `case.yaml`。
- `输入文件`：打开原始 PDF 或 JSON。
- `标准答案`：打开当前固化的 expected 文件。
- `候选解析预览`、`候选坐标预览`：从候选固化时保留下来的复核产物。
- `运行历史`：打开该用例的历史运行汇总页，查看每次运行的状态、报告和实际解析预览、坐标预览、差异预览等运行产物。

用例页不再直接展示最近一次测试的运行产物，避免文件预览区过长。需要排查历史结果时，从 `运行历史` 进入。

操作区包含：

- `停用` / `启用`：控制该用例是否参与测试。
- `更新答案`：重新调用接口生成新答案，确认后覆盖当前标准答案。
- `可视化编辑`：在可视化页面中点击文本或表格内容修改标准答案。
- `JSON编辑`：直接编辑标准答案 JSON。
- `名称编辑`：修改用例名称和说明，并同步更新相关配置。
- `归档删除`：将用例改为 `deleted` 状态，默认不再展示，也不会参与测试。

状态筛选默认只展示 `enabled` 和 `disabled` 用例。需要查看已归档删除的用例时，在状态筛选中选择 `deleted`。

`deleted` 用例的操作区包含：

- `恢复`：将用例恢复为 `enabled` 状态，并重新参与测试。
- `彻底删除`：永久清理该用例的可见文件和 MinIO 远端对象，页面中无法恢复。点击时会先弹出二次确认。

可视化编辑、JSON 编辑和名称编辑默认在新选项卡打开，避免丢失当前筛选状态。

页面右上角包含 MinIO 同步入口：

- `从 MinIO 刷新`：从团队共享 bucket 下载最新正式用例和候选用例到本机。
- `上传本地到 MinIO`：把本机当前正式用例和候选用例上传到团队共享 bucket。第一次迁移现有用例时先由负责人点击一次。

当前默认 bucket 为 `regression-mvp-dev`，对象前缀为 `regression_mvp/`。

MinIO 同步采用版本化 manifest。正常情况下，页面按钮不需要用户理解底层结构；如果本地和远端同时修改了同一文件，系统不会静默覆盖，会在以下目录生成冲突报告：

```text
regression_mvp/.sync_state/conflicts/
```

遇到冲突时，先打开冲突 JSON 查看具体文件，再决定采用本地版本、先刷新远端版本，或手动整理后重新上传。

## 8. 候选页

候选页用于生成和确认新测试用例。

生成候选用例时可以：

- 选择接口。
- 点击文件选择框上传一个或多个 PDF / JSON 文件。
- 填写备用路径。
- 填写用例名称。批量上传时会按文件名自动生成。

### ADE 异步解析

选择 `ade_jobs_async` 后，系统会提交 `POST /openapi/ade/jobs/submit`，自动携带输入文件的 SHA-256，轮询任务至 `completed`，再读取 `/data` 的 `content_list.content` 生成候选答案、解析预览和坐标预览。该链路依赖 API 与 ADE Worker 同时运行。

候选列表展示候选名称、接口、用例名、状态和文件预览。

点击候选名称进入详情页，可以：

- 查看输入文件、候选标准答案、解析预览、坐标预览。
- 修改候选用例名称和说明。
- `编辑标准答案 JSON`。
- `可视化编辑标准答案`。
- 对 `financial_merge_tables` 候选选择要合并的原始表格，并重新生成合并结果。
- `promote` 固化为正式用例。

候选页不直接新增说明列，避免表格过宽；说明和名称编辑集中放在候选详情页。

候选用例生成、编辑、可视化修改和 promote 后会自动尝试同步到 MinIO。如果其他同事新生成了候选，用本页右上角的 `从 MinIO 刷新` 拉取即可。

## 9. 报告页

报告页分为：

- 多接口汇总报告。
- 单接口测试报告。

Web UI 中默认只展示 HTML 报告入口。Markdown 和 JSON 文件仍会生成，但主要作为底层产物保留，不在普通入口中展示。

报告删除按钮用于清理无意义运行，例如未连接 VPN 导致的失败。删除行为是归档移动，不是硬删除：

```text
regression_mvp/reports/_archive/
```

删除后页面会自动刷新，并重建报告索引。如果仍看到已删除报告，通常是浏览器缓存或旧 Web 进程导致，刷新页面或重启 Web 即可。

## 10. 运行页

运行页用于查看 Web 触发的测试任务。

运行状态区展示：

- 目标接口。
- 开始和结束时间。
- 退出码。
- 当前状态。
- 日志入口。

Web 执行历史支持：

- 多接口运行：在汇总列打开多接口汇总报告。
- 单接口运行：在汇总列打开单接口详情和 HTML 报告。

页面显示时间统一按北京时间展示。

## 11. HTML 报告阅读

HTML 报告是测试人员和开发排查问题的主要入口。

核心区域：

- `Case Overview`：每个 case 的结果、产物和预览入口。
- `关键指标`：按接口类型展示中文指标，例如页数、元素数、表格数、匹配率、三大表数量等。
- `完整指标明细`：折叠展示原始 metrics。
- `差异摘要`：按严重程度、差异类型和高频路径汇总 diff。
- `完整差异指标明细`：折叠展示原始 diff metrics。
- `解析内容质量评估`：MinerU 与 ADE item 解析接口共用的三层结论、文本/表格/数字覆盖率和重点复核页。
- `Advanced Raw Diff Samples`：折叠展示按严重程度排序的字段级差异；仅在需要深入排查时展开。

MinerU / ADE 解析用例的状态含义：

- `passed`：契约和内容均在阈值内。
- `warning`：内容正常，但存在 item 拆分/合并、顺序或坐标等结构性抖动，不阻断测试。
- `suspected`：内容覆盖率、表格内容或财报数字出现需要人工复核的变化，测试视为失败。
- `failed`：接口失败或解析结果违反基础契约，例如结果为空、关键页或关键对象消失。

diff 严重程度含义：

| 级别 | 含义 |
| --- | --- |
| `blocker` | 接口失败、结果为空、无法继续比较 |
| `critical` | 整页、整表或核心结构明显缺失 |
| `major` | 重要字段、item 数、表格结构发生明显变化 |
| `minor` | 少量文本、坐标或低风险字段变化 |
| `info` | 已知动态字段或提示类差异 |

报告里的预览、overlay、PDF 等证据链接默认在新选项卡打开。

## 12. 常见问题

### API 检查失败

先打开：

```text
http://localhost:6300/swagger#/
```

如果打不开，说明 API 没启动或端口不对。

### 开代理后接口失败

测试 client 已配置为不读取系统代理，但业务 API 进程自己的网络请求仍可能受启动环境影响。稳定做法是关闭本机代理后重启 API，再运行测试；同时必须连接公司VPN才能访问MinerU服务。

### 报告删除后页面看起来没变

报告删除后会跳转刷新。如果仍看到旧记录，先强制刷新浏览器；如果还存在，重启 Web 进程。

### 预览为空但 JSON 不为空

通常说明该接口返回结构不是通用 MinerU item 列表，或者当前渲染器只支持其中一部分结构。优先打开 JSON 和 HTML 报告里的关键指标确认数据是否存在。

### 修改标准答案后测试仍失败

确认修改的是正式用例目录下的标准答案，而不是候选目录里的临时答案。正式用例页的 `JSON编辑` 或 `可视化编辑` 会直接更新正式用例。
