## 代码变更规范
- 只允许修改`src/ade/knowledge_graph/`和`tests/integration/kg_test/`下的代码。
- 代码要求简短清晰、可读性强。
- 疑问处理：存在不确定项时，必须先沟通确认，严禁直接改代码。
- 代码编写原则：优先使用简洁高复用实现；能复用内置/项目工具、原生库方法则直接使用，无新增依赖时优先采用成熟工具包封装能力，不重复手写底层原生逻辑。示例：向量点乘直接调用 numpy 内置方法，不自行从零实现。
- 工具复用：优先复用项目已有通用封装工具，禁止重复造轮子（例如，序列化用 `src/utils/json_utils.py`、计时用 `src/utils/stopwatch.py`）。
- 代码修改限制：禁止无意义格式微调（如加长分割线、无逻辑的冗余格式调整）。
- 临时文件管理：调试脚本、沙箱文件、临时产物等过程文件，无特殊要求全部删除。
