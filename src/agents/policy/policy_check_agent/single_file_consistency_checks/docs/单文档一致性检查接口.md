# 单文档一致性检查接口说明

版本：V1.2  
日期：2026-04-02

## 1. 目标

本接口用于单文档一致性检查，对接形式尽量与 Java 侧现有检查回调风格保持一致。

当前对接口径：

- `category` 固定返回 `CONSISTENCY`
- 对外主键统一使用 `checkReportId`
- 不再对外暴露 `taskId`

## 2. 接口列表

### 2.1 提交任务

`POST /api/policy/single-doc/consistency/jobs`

### 2.2 查询任务状态

`GET /api/policy/single-doc/consistency/jobs/{jobId}`

### 2.3 查询任务结果

`GET /api/policy/single-doc/consistency/jobs/{jobId}/result`

### 2.4 回调地址

`POST /result/consistency/callback`

## 3. 提交接口设计

### 3.1 请求体

```json
{
  "checkReportId": "REPT-20260401-0001",
  "fileId": "file_001",
  "docFileName": "授信审查制度.json",
  "docContent": [],
  "callbackUrl": "http://java-service/result/consistency/callback",
  "modelId": "model_bailian_policy_check",
  "maxJudgeConcurrency": 8
}
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `checkReportId` | string | 是 | Java 侧生成的报告 ID，作为本次检查主关联键 |
| `fileId` | string | 否 | 解析后文件 ID |
| `docFileName` | string | 否 | 文档原始名称 |
| `docContent` | array | 是 | Java 侧传入的 MinerU 解析 JSON |
| `callbackUrl` | string | 否 | 回调地址；不传则走服务默认配置 |
| `modelId` | string | 否 | 指定模型 |
| `maxJudgeConcurrency` | int | 否 | LLM 裁决并发数，默认 6，建议不超过 8 |

### 3.3 提交返回

```json
{
  "jobId": "8b9f31b2-60c8-4dc0-a293-4f0bfe3efb95",
  "checkReportId": "REPT-20260401-0001",
  "success": true,
  "message": "request accepted"
}
```

说明：

- `checkReportId` 是对外主键
- `jobId` 仅为 Python 内部异步任务 ID

## 5. 当前实现说明

- 代码层已统一支持 `checkReportId`
- 提交接口、回调结果、查询结果都已带上 `checkReportId`
- 不再要求或返回 `taskId`
- `jobId` 仍保留给 Python 内部异步任务查询使用
