# 单文档一致性检查代码流程说明

## 1. 入口与任务执行

- 接口入口：`POST /single-doc/consistency/jobs`
- 代码位置：`router.py`
- 执行模式：异步后台任务（`BackgroundTasks`）

处理流程：

1. 校验请求（`checkReportId`，且 `input_path`/`docContent` 至少一个存在）
2. 生成 `jobId`，写入任务文件（`storage/policy_check/single_doc_consistency_jobs/{jobId}.json`）
3. 后台执行 `_run_job_async`
4. 回调事件顺序：
   - `started`
   - `audited`
   - `completed`
   - 异常时改为 `error`

## 2. 服务主流程（规则抽取 + LLM 增强 + LLM裁决）

- 核心代码：`service.py` 的 `SingleDocConsistencyService.analyze_request/analyze_resource_file`

主链路：

1. 输入标准化
   - 请求转 `ResourceFile`（支持 `docContent` 或本地 `input_path`）
   - 解析 `model_id / max_candidates / max_judge_concurrency / llm_retry_attempts / check_types`
2. 文档初步分类（复用 shared）
   - `classify_doc_profile_with_llm_fallback`（关闭 LLM 时走 `classify_doc_profile`）
   - `map_doc_types_to_policy_doc_types`
   - 用于确定当前文档类型下的检查策略（可用 `check_types` 与 `slot_hints`）
3. 文档预处理与结构化抽取
   - 清洗文本（`MaterialCleaner`）
   - 构建 `MaterialStore`（`build_material_store`）
   - 抽取：
     - segments
     - 术语定义（terms）
     - 事实槽位（facts）
     - 交叉引用（references）
     - 文档锚点（anchors）
4. 规则侧候选问题生成
   - `term_definition_consistency`：术语定义 vs 实际使用
   - `fact_value_consistency`：同槽位出现多值
   - `cross_reference_consistency`：引用目标缺失（如“第X条/附件X/表X”）
5. LLM 候选增强（可选）
   - 分窗构造 `candidate_extractor` prompt
   - 结构化抽取补充候选
   - 与规则候选合并去重并截断到 `max_candidates`
6. 候选裁决
   - 启用 LLM：批量判断 candidate（一致/不一致/可能不一致/信息不足）
   - LLM失败：回退到规则兜底裁决
7. 结果聚合
   - 合并 issue 去重
   - 计算 `overall_status`（`inconsistent > possibly_inconsistent > insufficient_information > consistent`）
   - 产出 `statistics`（high/medium/low）与 metadata

## 3. 结果语义口径

每条 issue 包含：

- `issueId`、`issueType`
- `status`：`consistent / inconsistent / possibly_inconsistent / insufficient_information`
- `severity`：`high / medium / low`
- `summary/reasoning/suggestion`
- `confidence`
- `evidence`（页码、elementId、segmentId、quote、role）
- `attributes`（候选上下文、槽位信息等）

回调层会将 status 映射为 Java 侧口径：

- `inconsistent -> fail`
- `possibly_inconsistent / insufficient_information -> uncertain`
- 其他 -> `pass`

## 4. 配置项与默认值

请求可调参数（`schemas.py`）：

- `modelId`：默认 `model_bailian_policy_check`
- `enableLlm`：默认 `true`
- `maxCandidates`：默认 `24`
- `maxJudgeConcurrency`：默认 `12`
- `llmRetryAttempts`：默认 `3`
- `checkTypes`：默认
  - `term_definition_consistency`
  - `fact_value_consistency`
  - `cross_reference_consistency`

## 5. 用时
本地测试34页pdf输入完成时间在几秒内。


## 6. 本地测试脚本

本目录已新增脚本：

- `single_file_consistency_local_test.py`

能力：

- 读取本地 JSON（单文件或目录批量）
- 支持“无命令行演示模式”：直接改脚本顶部 `DEFAULT_*` 配置
- 支持覆盖 `model_id / enable_llm / max_candidates / max_judge_concurrency / llm_retry_attempts / check_types / 并发数`
- 打印 `started -> audited -> completed` 回调结构
- 落盘完整模型输出与回调 payload
