# 单文件风险信号识别接口

## 1. 目标

该接口用于对单个文档执行风险信号识别，并通过异步回调返回结果。

- 能力范围：`single_file_risk_signal_checks`
- 提交接口：`POST /api/policy/single-file/risk/jobs`
- 回调接口：`POST /result/risk/callback`
- `category` 固定返回：`RISK_SIGNAL`
- 回调模式：`started -> audited -> completed`，失败时回调 `error`

`audited` 事件会在单个文件识别完成后，一次性回调全部风险信号结果，不做逐条流式回调。

## 2. 检查范围

当前 MVP 重点识别以下高风险表述：

- 模糊用语：`VAGUE_EXPRESSION`
- 极端表达：`EXTREME_EXPRESSION`
- 免责或责任弱化条款：`LIABILITY_DISCLAIMER`
- 单方解释权表述：`UNILATERAL_INTERPRETATION`

当前实现采用“两阶段”方式：

1. 规则召回高风险候选句
2. LLM 进行结构化裁决

如果模型调用失败，会降级为规则候选结果，并将状态保守标记为 `uncertain`。

## 3. 提交接口

- 方法：`POST /api/policy/single-file/risk/jobs`
- Content-Type：`application/json`

### 3.1 请求字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `checkReportId` | 是 | Java 侧任务主键，也是回调归并主键 |
| `fileId` | 否 | 待识别文件 ID，不传时默认回落为 `checkReportId` |
| `fileName` | 否 | 待识别文件名，不传时默认 `${fileId}.json` |
| `callbackUrl` | 否 | 完整回调地址，不传时使用 `POLICY_CALLBACK_BASE_URL + /result/risk/callback` |
| `docContent` | 是 | MinerU 解析后的文档 JSON 列表 |
| `modelId` | 否 | 模型 ID，默认 `model_bailian_policy_check` |
| `enableLlm` | 否 | 是否启用 LLM 裁决，默认 `true` |
| `maxCandidates` | 否 | 最大候选数，默认 `24` |
| `maxJudgeConcurrency` | 否 | 模型裁决并发，默认 `6` |
| `llmRetryAttempts` | 否 | 模型失败重试次数，默认 `3` |

### 3.2 `docContent` 输入要求

`docContent` 必须符合项目当前 MinerU 解析结构，也就是 `ResourceFile.content: List[Item]`。

最常见的是 `text` 类型，示例字段如下：

```json
{
  "page": 1,
  "type": "text",
  "bBox": {
    "l": 10,
    "t": 10,
    "r": 200,
    "b": 30,
    "coord_origin": "TOPLEFT"
  },
  "value": "本协议最终解释权归我方所有。",
  "md": "本协议最终解释权归我方所有。",
  "file_id": "doc_001",
  "element_id": 1
}
```

### 3.3 请求示例

```json
{
  "checkReportId": "RISK-20260402-001",
  "fileId": "doc_001",
  "fileName": "contract_clause.json",
  "docContent": [
    {
      "page": 1,
      "type": "text",
      "bBox": {
        "l": 10,
        "t": 10,
        "r": 200,
        "b": 30,
        "coord_origin": "TOPLEFT"
      },
      "value": "本协议最终解释权归我方所有。",
      "md": "本协议最终解释权归我方所有。",
      "file_id": "doc_001",
      "element_id": 1
    }
  ],
  "modelId": "model_bailian_policy_check",
  "enableLlm": true
}
```

### 3.4 提交响应

```json
{
  "success": true,
  "checkReportId": "RISK-20260402-001",
  "jobId": "0e64dd54-86b7-4c7f-a5f0-26d39dba3c28",
  "message": "request accepted"
}
```

说明：

- `checkReportId` 是对外主键
- `jobId` 仅为 Python 内部异步任务 ID，Java 可不依赖

## 4. 回调事件

### 4.1 started

表示任务已受理并开始执行。

```json
{
  "event": "started",
  "checkReportId": "RISK-20260402-001",
  "fileId": "doc_001",
  "category": "RISK_SIGNAL",
  "data": {
    "fileStatus": "P"
  }
}
```

### 4.2 audited

表示该文件已识别完成，并一次性返回全部风险信号结果。

```json
{
  "event": "audited",
  "checkReportId": "RISK-20260402-001",
  "fileId": "doc_001",
  "category": "RISK_SIGNAL",
  "data": {
    "fileId": "doc_001",
    "docFileName": "contract_clause.json",
    "fileStatus": "F",
    "results": [
      {
        "scope": "file",
        "category": "RISK_SIGNAL",
        "fileId": "doc_001",
        "docFileName": "contract_clause.json",
        "issueType": "UNILATERAL_INTERPRETATION",
        "controlResult": {
          "status": "fail",
          "level": "HIGH",
          "title": "检测到单方解释权表述",
          "detail": "该句将解释权单方归属于一方，可能形成高风险表述。",
          "suggestion": "建议删除单方解释权表述，改为双方确认或按制度解释。",
          "degraded": false
        },
        "attributes": {
          "matchedKeywords": ["最终解释权归"]
        },
        "evidence": [
          {
            "sequenceId": 1,
            "fileId": "doc_001",
            "elementIds": [1],
            "pageNo": 1,
            "quote": "本协议最终解释权归我方所有。",
            "recommendation": "该句将解释权单方归属于一方，可能形成高风险表述。",
            "role": "mention"
          }
        ]
      }
    ]
  }
}
```

### 4.3 completed

表示文件级任务已经全部结束，返回汇总统计。

```json
{
  "event": "completed",
  "checkReportId": "RISK-20260402-001",
  "fileId": "doc_001",
  "category": "RISK_SIGNAL",
  "data": {
    "totalIssues": 2,
    "high": 1,
    "medium": 1,
    "low": 0,
    "passed": 0,
    "failed": 1,
    "uncertain": 1,
    "durationSeconds": 8.2,
    "description": "发现 2 条高风险表述，建议重点复核免责、模糊或单方解释类语句。"
  }
}
```

### 4.4 error

表示任务执行失败。

```json
{
  "event": "error",
  "checkReportId": "RISK-20260402-001",
  "fileId": "doc_001",
  "category": "RISK_SIGNAL",
  "data": {
    "errorMessage": "RuntimeError: ..."
  }
}
```

## 5. 字段说明

### 5.1 顶层字段

| 字段 | 说明 |
| --- | --- |
| `event` | 回调事件类型：`started / audited / completed / error` |
| `checkReportId` | Java 侧任务主键 |
| `fileId` | 文件 ID |
| `category` | 固定为 `RISK_SIGNAL` |
| `data` | 事件数据体 |

### 5.2 `results[]` 字段

| 字段 | 说明 |
| --- | --- |
| `scope` | 固定为 `file` |
| `category` | 固定为 `RISK_SIGNAL` |
| `fileId` | 文件 ID |
| `docFileName` | 文件名 |
| `issueType` | 风险类型 |
| `controlResult.status` | 识别结果：`pass / fail / uncertain` |
| `controlResult.level` | 风险等级：`HIGH / MEDIUM / LOW / NONE` |
| `controlResult.title` | 风险摘要 |
| `controlResult.detail` | 风险原因 |
| `controlResult.suggestion` | 修订建议 |
| `controlResult.degraded` | 当前固定为 `false` |
| `attributes` | 附加属性，如命中关键词 |
| `evidence[]` | 证据列表 |

### 5.3 `evidence[]` 字段

| 字段 | 说明 |
| --- | --- |
| `sequenceId` | 证据顺序 |
| `fileId` | 文件 ID |
| `elementIds` | MinerU 元素 ID 列表 |
| `pageNo` | 页码 |
| `quote` | 原文片段 |
| `recommendation` | 风险原因或复核建议 |
| `role` | 当前固定为 `mention` |

## 6. 当前实现边界

- 当前先做单文件风险表述识别，不做跨文件比对。
- 候选召回先基于风险词和句式，LLM 负责结构化裁决。
- 当前重点覆盖：`VAGUE_EXPRESSION`、`EXTREME_EXPRESSION`、`LIABILITY_DISCLAIMER`、`UNILATERAL_INTERPRETATION`。
- 当前不区分“条款风险”和“业务风险”，只识别表述层面的风险信号。
- 结果默认保留可追溯证据位置，方便前端高亮和人工复核。
