# 单文件完整性检查代码流程说明

## 1. 入口与任务执行

- 接口入口：`POST /single-file/completeness/jobs`
- 代码位置：`router.py`
- 执行模式：异步后台任务（`BackgroundTasks`）

处理流程：

1. 校验请求（`checkReportId`、`docContent`）
2. 生成 `jobId`，写入任务文件（`storage/policy_check/single_file_completeness_jobs/{jobId}.json`）
3. 后台执行 `_run_job_async`
4. 按事件顺序回调：
   - `started`
   - `audited`
   - `completed`
   - 异常时改为 `error`

## 2. 服务主流程（规则优先 + LLM 兜底）

- 核心代码：`service.py` 的 `SingleFileCompletenessCheckService.analyze_request/analyze_resource_file`

主链路：

1. 输入标准化
   - 将请求转为 `ResourceFile`
   - 解析 `model_id / enable_llm / llm_retry_attempts`
2. 文档初步分类（复用 shared 能力）
   - 调用 `shared/doc_profile.py` 中的 `classify_doc_profile_with_llm_fallback`
   - 将分类结果映射到策略文档类型（`map_doc_types_to_policy_doc_types`）
   - 该结果用于后续“按文档类型叠加/替换专属完整性规则”（如证照类规则）
3. 文档预处理
   - 清洗文本（`MaterialCleaner`）
   - 构建证据块（`build_material_store`）
   - 组装 segment 并去重
4. 确定“本次要检查的必查项”
   - 优先级：
     1. `requiredSections`（显式指定）
     2. `documentType`（显式 profile）
     3. LLM profile 分类（置信度阈值 `>= 0.7`）
     4. LLM group 分类（置信度阈值 `>= 0.55`）
     5. 默认回退：`["目的", "适用范围"]`
5. 构建有效检查计划
   - 通用规则来自 `profiles.py -> SECTION_RULES`
   - 若识别到特定证照类文档类型，会叠加或替换为类型专属规则（`DOC_TYPE_COMPLETENESS_RULES`）
6. 逐项检查章节
   - 先规则匹配：
     - 标题匹配（`satisfactionMode=section`）
     - 正文语义模式匹配（`satisfactionMode=element`）
   - 规则失败时（`status=fail`）若启用 LLM，则进入语义兜底判断：
     - 可将结果提升为 `pass`
     - 或标记为 `uncertain`（待人工复核）
7. 聚合输出
   - `overallStatus` 规则：`fail > uncertain > pass`
   - 汇总 `statistics.pass/fail/uncertain`
   - 输出 item 级 evidence 与 attributes

## 3. 结果语义口径

每个检查项至少包含：

- `status`: `pass | fail | uncertain`
- `checkPoint`: 检查点编码
- `sectionName`: 章节名
- `summary/reasoning`: 说明文字
- `evidence`: 证据（页码、elementId、文本）
- `attributes`:
  - `matchedBy`: `title/content/llm_semantic/llm_uncertain/missing`
  - `satisfactionMode`: `section/element/missing`
  - `isStandaloneSection`: 是否独立成章
  - `confidence`: LLM 兜底场景可带置信度

## 4. 配置项与默认值

请求可调参数：

- `modelId`：默认 `model_bailian_policy_check`
- `enableLlm`：默认 `true`
- `llmRetryAttempts`：默认 `2`（限制 `1~6`）
- `requiredSections`：可强制覆盖必查项
- `documentType`：可强制指定 profile

## 5. 用时与统计建议

- 测试用的34页pdf完成时间在几秒内
- 受影响因素：
  - 文档段落数量（segment 数）
  - LLM 调用次数（profile/group/section_judge）
  - `llmRetryAttempts`

## 6. 本地测试脚本

- `single_file_completeness_local_test.py`

用途：

- 读取本地 JSON 输入
- 直接修改脚本顶部 `DEFAULT_*` 配置后运行
- 支持覆盖 `model_id / enable_llm / llm_retry_attempts / 并发数`
- 按 `started -> audited -> completed` 打印回调结构
- 落盘完整模型输出与回调 payload，便于回归和对比
