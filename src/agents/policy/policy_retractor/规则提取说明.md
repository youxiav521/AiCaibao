# 规则提取接口说明

## 1. 接口目标

该接口用于对 MinerU 解析后的政策文件进行规则提取，输出结构化的 `framework -> requirements -> controls` 结果，供后续规则审核、规则入库和检查执行使用。


## 2. 输入输出概览

### 输入

- 输入文件：MinerU 转换后的 JSON 文件
- 当前仅支持类似 `*_mineru_converted.json` 的输入格式

### 输出

- 返回一个规则提取结果 JSON
- 顶层结构：

```json
{
  "frameworkId": "string",
  "fileId": "string",
  "name": "string",
  "status": "PENDING_REVIEW|ERROR|APPROVED|REJECTED",
  "description": "string",
  "requirements": [
    {
      "requirementId": "string",
      "frameworkId": "string",
      "title": "string",
      "description": "string",
      "sourceText": "string",
      "status": "PENDING_REVIEW|ERROR|APPROVED|REJECTED",
      "sourceLocation": {
        "fileId": "string",
        "elementIds": [1, 2]
      },
      "controls": [
        {
          "controlId": "string",
          "requirementId": "string",
          "status": "PENDING_REVIEW|ERROR|APPROVED|REJECTED",
          "content": "string",
          "controlType": "qualification_check|document_check|quantitative_check|fund_use_check|collateral_check|prohibited_item_check|monitoring_check",
          "risk": "HIGH|MEDIUM|LOW",
          "sourceText": "string",
          "logicDescription": "string",
      "sourceLocation": {
        "fileId": "string",
        "elementIds": [1, 2]
      }
        }
      ]
    }
  ]
}
```

## 3. 字段说明

### 3.1 framework

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `frameworkId` | string | 是 | 规则框架唯一标识，格式为 `FW-<fileId>` |
| `fileId` | string | 是 | 文件唯一标识，来源于输入文件名主干 |
| `name` | string | 是 | 当前文件对应的规则框架名称 |
| `status` | string | 是 | 当前框架状态，默认一般为 `PENDING_REVIEW` |
| `description` | string | 否 | 当前框架摘要描述 |
| `requirements` | array | 是 | requirement 列表 |

### 3.2 requirement

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `requirementId` | string | 是 | requirement 唯一标识，格式为 `REQ-<32位uuidhex>` |
| `frameworkId` | string | 是 | 所属 framework 标识 |
| `title` | string | 是 | requirement 标题 |
| `description` | string | 是 | requirement 描述 |
| `sourceText` | string | 是 | requirement 对应的原文片段 |
| `status` | string | 是 | requirement 状态 |
| `sourceLocation` | object | 是 | requirement 溯源位置 |
| `controls` | array | 是 | control 列表 |

### 3.3 control

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `controlId` | string | 是 | control 唯一标识，格式为 `RULE-<32位uuidhex>` |
| `requirementId` | string | 是 | 所属 requirement 标识 |
| `status` | string | 是 | control 状态 |
| `content` | string | 是 | control 的核心控制点描述 |
| `controlType` | string | 是 | control 的检查大类 |
| `risk` | string | 是 | 风险等级：`HIGH` / `MEDIUM` / `LOW` |
| `sourceText` | string | 是 | control 对应的原文片段 |
| `logicDescription` | string | 是 | 面向后续检查 agent 的执行说明 |
| `sourceLocation` | object | 是 | control 溯源位置 |

### 3.4 sourceLocation

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `fileId` | string | 是 | 来源文件 ID |
| `elementIds` | array[int] | 是 | 来源元素 ID 列表，对应 MinerU 输出中的 element 标识；一个 requirement/control 可溯源到多个元素 |

## 4. controlType 取值说明

当前 `controlType` 只做大类归档，不承担过细的执行判断。

| 枚举值 | 说明 |
| --- | --- |
| `qualification_check` | 主体资格、准入条件、适用范围、治理和信用要求等 |
| `document_check` | 文件、材料、批件、合同、证明、签章、原件等核对 |
| `quantitative_check` | 比例、金额、面积、期限、阈值、测算等量化要求 |
| `fund_use_check` | 资金用途、专款专用、用途限制、回款归集等 |
| `collateral_check` | 抵押、质押、保证、担保有效性、抵押登记、评估等 |
| `prohibited_item_check` | 禁止性事项、不得做什么的约束 |
| `monitoring_check` | 贷后检查、持续监控、风险预警、重大事项跟踪等 |

说明：

- `controlType` 是供 Java 侧快速分类使用的“检查大类”
- 具体检查规则、字段映射、材料清单、判定分支，建议由后续检查 agent 基于 `content + sourceText + logicDescription` 继续细化

## 5. logicDescription 使用说明

`logicDescription` 的作用不是复述原文，而是提供后续检查 agent 可直接利用的检查说明。

通常包含以下信息：

- 检查对象：检查谁、什么材料、什么行为
- 检查动作：核对、确认、比对、判断
- 判定标准：满足什么条件算通过，不满足算不通过
- 检查时点：审批前、放款前、贷后、出现某情况时等


## 6. 状态字段说明

当前常见状态值：

| 状态值 | 说明 |
| --- | --- |
| `PENDING_REVIEW` | 已抽取，待人工或后续流程确认 |
| `ERROR` | 当前抽取过程中出现异常或结果不完整 |
| `APPROVED` | 预留状态 |
| `REJECTED` | 预留状态 |

说明：

- 当前提取结果通常默认返回 `PENDING_REVIEW`
- Java 侧如需业务流转，可复用该字段或在外层增加自己的审核状态
